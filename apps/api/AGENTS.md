# Backend organization and dependency rules

Organize code by business capability under `src/modules`, using familiar Nest component names inside each feature. Keep small features flat; add `commands`, `queries`, `controllers`, `guards`, `services`, `integrations`, or `workers` folders when navigation benefits. Do not repeat architectural-layer folders or create modules solely to register a layer. Create a submodule when it owns a capability or isolates a runtime. Keep HTTP and worker entry points separate when both exist.

Business models, repository/session ports, and business operations designated as plain stay independent of Nest, transport contracts, Drizzle, and provider SDKs. Nest can construct a plain service with a factory provider in its owning feature module. Controllers, guards, and pipes handle transport/admission; services coordinate operations; models own invariants; repositories and integrations own external details. Better Auth owns authentication mechanics; Gloups owns account identity, ownership, and lifecycle rules.

Use Nest CQRS for Gloups-owned commands and queries. Register `CqrsModule.forRoot()` once in the application entry point. Messages remain plain classes; decorated command/query handlers are thin Nest adapters that delegate to plain services constructed by feature factories. Commands perform state changes; query services depend only on models, messages, other read operations, and read ports. They must not import write ports, mutating operations, ORM clients, or buses. Keep read/write interfaces distinct even when one repository and database implement both. Add events or sagas when a capability needs them.

Validate HTTP input before dispatching commands. The existing `/api/me` admission flow dispatches `ResolveAccountCommand` to verify the session and ensure its Gloups account exists, then `GetCurrentAccountQuery` reads that account using the verified identity returned by the command. Preserve this first-access provisioning behavior explicitly; queries never create missing accounts. Better Auth's own HTTP protocol stays within its integration.

Cross-feature imports must use an explicit public contract. Export only the TypeScript contracts and Nest provider tokens a consumer needs. Do not expose SDK engines or globally injectable database connections. Keep both source imports and Nest module dependencies acyclic; `forwardRef` is not a way around that rule. ORM/SDK access belongs only in repositories, integrations, and approved wiring.

Register each new source file's feature and responsibility in `tools/architecture-policy.ts`. This explicit policy does not infer responsibilities from folder or filename conventions. Update public contracts, permitted Nest exports, and approved external framework modules deliberately. CQRS handlers cannot access repositories or integrations directly. `bun run check:boundaries` checks the policy and its regression fixtures in CI; `bun run test:cqrs` exercises the real compiled Nest buses with isolated business ports.

During organizational refactors, preserve HTTP contracts, authentication policy, SQL migrations, provider behavior, and readiness semantics. Keep unrelated fixes separate and rerun the existing acceptance journeys.
