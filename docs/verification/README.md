# Verification records

Keep dated evidence here. A record identifies its scope, revision, exact commands,
results, actual HTTP/app/provider boundary, devices/runtimes, synthetic data,
failures and limitations. Source screenshots and another app's checks are not new
repository evidence.

For documentation changes, verify remote identity/privacy, default branch,
actual files, local Markdown targets/anchors, Git diff, task/decision consistency,
no secrets/excluded references, absence of application scaffolding and the merged
PR. The tooling setup also verifies installation, lint/format configuration,
Turborepo builds, Changesets and commit hooks. Product E2E acceptance remains
dependent on a real product app or service.

Future acceptance follows [VERIFICATION](../VERIFICATION.md). Never retain real
health records or credentials in a record, fixture or capture.
