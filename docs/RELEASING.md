# Delivery boundaries

## Git integration

Run relevant local checks, commit, push and merge a PR into main for each
completed assigned task. Attach the PR to the Codex chat when available.
GitHub Actions usage is exhausted; do not add automatic workflows or wait for CI.
The initial repository README provides a base branch for the documentation PR.

## Product implementation

The documentation workspace builds locally. Changesets records package versions;
the package is private and no publishing/deployment workflow is configured.
Before product application work, approve the relevant specifications/contracts,
an implementation packet,
actual tooling versions/targets and provider responsibilities. A merged design
draft is not that approval. Domain agents must use accepted interface versions.

## Deployment and app distribution

Git merges do not deploy services, register apps, change DNS, publish Canny,
invite people, send campaigns or distribute mobile builds. Those actions require
specific scope/authorization and verified target accounts/environments. Do not
copy old signing material, production data or secret configuration into Git.

Before worldwide availability, record actual iOS/Android stores/markets, allowed
populations, provider/catalog coverage, language/formatting support, consent/legal
copy, pricing/currency and support limits. Validate French and English on real
platforms alongside international date, unit, timezone and offline journeys.

Release evidence includes the delivered revision, device/runtime, persistence,
failed/denied paths, restore/recovery, rights/retention and relevant operating
controls. Keep consumer release evidence separate from future HIPAA BAA/HDS
qualification. No availability or certification claim is established by a plan.
